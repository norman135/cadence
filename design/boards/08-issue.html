ATL-142 Backend Bug

Offline sync drops edits made on the train

When the connection flaps (tunnels, trains), edits made offline are sometimes lost. The outbox replays queued mutations in parallel, so a later edit can land before an earlier one and the server rejects it with 409 Conflict.

Replaying in order per issue should fix it. Conflicts need to surface in the activity feed instead of disappearing.

Acceptance criteria
Queued edits replay in the order they were made
Replays for different issues still run in parallel
A rejected edit shows in the activity feed with a retry action
